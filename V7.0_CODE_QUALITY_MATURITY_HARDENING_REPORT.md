## Core complexity reductions

- `app.main`: 439 -> 204 lines.
- command-runtime `_terminal`: 353 -> 15 lines.
- `RunOrchestrator._execute`: 328 -> 79 lines.
- `bootstrap`: 302 -> 167 lines.
- browser capture `_run`: 292 -> 32 lines and moved into an independent adapter module.
- terminal workspace builtin dispatcher: 259 -> 13 lines, split into bounded command families.
- packet data contracts moved into a dedicated model module so packet analysis remains below the 1,000-line module ceiling.

The refactors retain the existing startup visual contract, capture semantics, resource governance, persistence behavior, terminal command behavior, and enterprise authorization boundaries.

## Async regression coverage

Added real `pytest-asyncio` tests for:

- server lifespan and data-root lease release;
- correlation/security-header middleware behavior;
- invalid Content-Length rejection before dispatch;
- 16-way concurrent enterprise live requests.

`pytest-asyncio` is now part of the development dependency set.

## Exception and dynamic-code audit

- Modern broad `Exception` handlers reduced from 311 to 306.
- The architecture-debt ratchet is tightened to 306 total and 1 in the proxy path; future increases fail the gate.
- Quality 20D reports zero unjustified broad handlers.
- Bare `except:` remains zero.
- Direct runtime `exec()` and `eval()` are zero across modern source; the prior static report's text-level counts did not represent live runtime builtin calls.
- `BaseException` handlers remain limited to five deliberate transaction/process-validation cleanup boundaries and are ratcheted by regression tests.

## Type safety

High-risk network and runtime boundaries were prioritized rather than filling UI callback annotations with meaningless `Any` solely for a percentage. The interception bridge is now fully annotated. Same-metric modern fully annotated function coverage increased from 95.38% to 96.92%.

## Documentation

Documentation work focused on public/high-risk APIs:

- terminal process and environment API;
- packet runtime and transform API;
- capture controller lifecycle;
- enterprise operation authorization guard;
- interception bridge lifecycle;
- browser capture helpers and other refactored core paths.

This raises function docstring coverage from 0.34% to 7.17% under the same modern-source AST metric. It is intentionally not a blanket auto-generated 60% target; additional documentation should continue module-by-module with semantic content.

## Runtime logging

Modern and frozen runtime trees contain zero direct `print()` calls. Command-line build/validation scripts intentionally retain stdout output because stdout is their interface; replacing those with application logging would reduce script usability without improving runtime observability.
