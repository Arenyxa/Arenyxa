# Arenyxa V6.5.6 — Independent Re-audit, Security & Crash Consistency

V6.5.6 is a corrective reliability release produced by independently re-auditing the V6.5.5 candidate rather than assuming the previous test result was sufficient.

## Correctness and security changes

- Plugin audit policy now inspects the integer flag argument emitted by CPython for `os.open()`. A plugin without `storage` permission can no longer bypass write policy with `O_WRONLY`, `O_CREAT`, `O_TRUNC`, `O_APPEND`, or `O_RDWR`.
- Repair Center dependency detection and dependency repair share `StartupHealthScanner.REQUIRED_MODULES`; `cryptography` and future required modules cannot drift between the two paths.
- Repair Center plugin checks reuse `PluginManifest.load()`, so health scanning, quarantine, and runtime loading enforce the same manifest and permission contract.
- Distributed Worker registry validation now bounds names, validates Secret Vault references and boolean state, and rejects duplicate worker IDs rather than silently collapsing them later.

## Workflow recovery and crash consistency

- Schema migration 11 adds an immutable `definition_json` snapshot to each Workflow execution. New interrupted executions resume from the exact definition they started with even if the saved Workflow is later edited or removed.
- Workflow resume still verifies the semantic `definition_hash`; corrupt or mismatched snapshots do not weaken checkpoint safety.
- Startup recovery treats a `ready` output Revision as the durable Workflow commit point. A crash after Revision finalization but before execution-state finalization is reconciled to `completed` / `completed_with_errors`, not misclassified as a failed resume chain.
- Completed Workflow lineage is reconstructed idempotently only when the canonical `produced` edge is missing. Startup no longer rewrites every historical lineage edge.
- Same-Dataset transformations now set the new Revision's `parent_revision` to the actual source Revision, not the Dataset's unrelated current head.
- A lineage-write failure after a ready output commit is diagnostic only; it cannot downgrade already committed output to a failed Workflow.
- Workflow runtime owns active cancellation tokens. Application shutdown stops new Workflow work, cancels active background executions and waits with a bounded timeout before database maintenance.

## Dataset lineage and memory safety

- Ready non-Workflow Dataset Revisions missing their canonical `version_of` edge can be repaired idempotently at bootstrap. Workflow-owned output Revisions are excluded from this generic path to avoid inventing direct Run lineage.
- Dataset data commit is no longer reported as failed merely because post-commit lineage persistence encountered a transient error.
- `WorkflowEngine.buffer_size` is now an enforced memory boundary for root ingestion, node fan-out queues, and terminal outputs. It was previously validated but unused.

## Process cleanup and version consistency

- tshark/dumpcap shutdown attempts both terminate and kill with bounded waits, continues cleanup across components, and reports a stable `CAPTURE_SOURCE_STOP_TIMEOUT` instead of leaking raw timeout exceptions.
- Runtime version strings derive from `arenyxa.__version__` where practical; server health, User-Agent defaults, project metadata, window titles and runtime tooling therefore move together with the package version.

All changes retain the V6.5 non-destructive recovery rule: formal user data, ready Dataset output, capture evidence, and interrupted checkpoints are preserved unless a user explicitly deletes them.

## Additional lifecycle and compatibility hardening

- ApplicationContext shutdown is serialized and idempotent so concurrent close/repair/integration requests cannot tear down Scheduler, Runner, Capture, Workflow Runtime, or Terminal twice.
- Capture start failures now best-effort stop partially-created adapters; concurrent Capture stop paths are serialized so one session cannot be finalized twice.
- Data-root lease acquisition clears cached ownership when owner-metadata persistence fails, preventing a retry from mistaking a closed file handle for a valid OS lock.
- Plugin compatibility is explicit: only supported Plugin API versions and compatible `min_app_version` values are loadable. Incompatible but structurally valid plugins are preserved/disabled rather than quarantined as corruption. Version metadata is bounded before integer parsing.
- Qt background work disables page callbacks during application shutdown, removes queued Arenyxa QRunnables when possible, and performs a bounded quiesce before widgets are destroyed. Callback exceptions are contained at the UI boundary.
- Terminal hard-stop paths now reap child process handles after kill, reducing leaked Windows process/pipe handles across repeated sessions.
- Headless Server performs the same durable runtime recovery as Desktop after obtaining the data-root lease.
- Runner pause/resume/final-state transitions share a per-run lock. Its pre-existing five-positional-argument `_execute()` integration contract remains valid; the new lock is optional keyword-only state.
- Workflow active-operation tracking uses a monotonic operation key rather than `id(token)`, so two concurrent executions that deliberately share one CancellationToken remain independently visible to shutdown.
- Python 3.11 grammar is checked across every packaged source file; release metadata remains aligned at 6.5.6.
