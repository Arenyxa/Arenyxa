# Arenyxa v7.0 — Zero Trust, DLP and SQLite Resilience Hardening

Date: 2026-08-19

## Audit dispositions

- TLS Inspector: `ssl.create_default_context()` was already validating certificates and hostnames by default. The invariant is now explicit (`CERT_REQUIRED`, `check_hostname=True`) and regression-tested.
- DNS Analyzer: this desktop client is not an amplification server. Response/resource amplification is now bounded by address/record/text budgets and EDNS UDP payload 1232.
- Zero Trust: resource-level dynamic policy is integrated into Enterprise operation authorization with current authentication age, enrolled-device posture, authorization generation, network-trust/risk/MFA telemetry hooks, fail-closed missing telemetry and non-elevating supplemental context.
- DLP: central HTTP egress plus visible intercepting-proxy Proxy/Repeater traffic are inspected in monitor/enforce modes. Findings never persist secret values. Opaque CONNECT tunnels cannot be payload-inspected without TLS interception.
- SQLite: local SQLite remains a durable single-writer WAL backend. It is explicitly advertised as `serialized-wal`, recommends one parallel writer / four worker slots, and directs sustained high concurrency or multi-host deployments to PostgreSQL. No durability setting was weakened to improve benchmarks.
- Exception handling: `except Exception` does not catch `KeyboardInterrupt`/`SystemExit`; bare catches are prohibited and BaseException boundaries are allow-listed. The broad-exception ratchet remains enforced.
- Shutdown: application shutdown is dependency-ordered instead of source-order fixed, while retaining best-effort cleanup.
- Transactions: commit failure now attempts rollback, preserves the original commit exception, and always closes the non-reused connection.

## SQLite worker-slot evidence

The bundled 64-job validation remains invariant-safe at 1/2/4/8/16/32 slots (0 errors, no lease/state invariant violations), but 32-slot p99 can be hundreds of milliseconds because SQLite serializes writers. The validator therefore keeps `recommended_slots=4`; PostgreSQL is the intended sustained 32/64-worker backend.
