# Arenyxa v7.0 Stability & Maintainability Optimization — 2026-08-17

## Baseline

This increment is based on `Arenyxa_v7.0_GitHub_Publication_Ready_Source.zip` and keeps the
public/runtime version at 7.0.0. The approved startup implementation remains frozen.

## Changes

### 1. Workflow runtime topology performance

`WorkflowEngine.execute()` now advances DAG nodes with Kahn-style remaining-parent counters.
The prior implementation re-scanned every workflow node for each completed edge, producing
quadratic behavior on large DAGs. The new path is O(V + E) while preserving failure routing,
cycle detection, cancellation checkpoints, output limits and node execution accounting.

A local deterministic benchmark using a 2,500-node linear DAG executed five times improved from
approximately 1.9545 seconds on the publication baseline to 0.0750 seconds on this tree (~26x).
The benchmark is not a release performance guarantee; it is evidence for the removed algorithmic
hotspot.

### 2. Workflow memory safety

Production workflow error history is now bounded by the same execution buffer safety policy used
for root ingestion, per-node queues and terminal outputs. This prevents a failure-routed workflow
from accumulating an unbounded diagnostic list.

`WorkflowDebugger` now:

- streams input iterables instead of materializing them into an unbounded list;
- bounds queued work, terminal output history and error history;
- bounds fan-out and retry insertion;
- fails closed on buffer exhaustion;
- clears partial queued state when `prepare()` fails;
- preserves empty current-item mappings in debugger snapshots.

### 3. RunOrchestrator resource lifecycle maintainability

Request admission/lease/Future ownership and result-batch persistence were extracted from the
large `_execute()` method into dedicated private lifecycle helpers. Global request permits and
per-host leases retain their existing cancellation/shutdown behavior, but the acquire/release
paths are now auditable in one place.

Per-host semaphore release and reference-count updates now occur in one limiter critical section,
removing an unnecessary transient state mismatch between the semaphore and the gate's `users`
count.

### 4. Capture backpressure consistency

`CaptureController` now normalizes the published queue capacity to the actual Queue capacity and
caps `flush_size` at that capacity. A configuration can no longer report an invalid/non-positive
capacity while silently constructing a one-item Queue, and the writer no longer waits for a batch
size that the queue can never hold.

### 5. Small hot-path cleanup

Remote worker partition filtering now constructs the requested worker-id set once instead of once
per worker during the list comprehension.
